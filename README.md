# Salacia · 水下自主轻型关节式智能装置

> **S**ubmersible **A**utonomous **L**ightweight **A**rticulated **C**ognizant **I**ntelligent **A**pparatus
> 
> —— 以水神之名，探索水下感知与作业

Salacia 是一套面向**水下观察与遥控作业**的轻型关节式机器人平台（ROV）：10 路关节舵机 + 6 路推进器、硬件编码 1080p 实时图传、岸端 AI 目标识别、M33 本地姿态稳定闭环，运行在 **STM32MP257 异构多核 SoC** 上，整机物料成本控制在 **US$500 以内**。

项目由"良子说的都队"完成：四个软件工程、**6 万行自研代码**、**225+ 项自动化测试用例**外加 48 项局域网一致性验证，从 SoC 双核固件到岸端 GUI 全栈自研。

## 为什么是 STM32MP257

水下机器人是"视频图传 + 实时控制 + 网络服务"三重负载叠加的典型场景。多数参赛作品采用的 ESP32-S3 是一颗优秀的 Wi-Fi MCU，但在本项目的需求面前存在代差：

| 维度 | ESP32-S3（常见方案） | **STM32MP257（本项目）** |
|---|---|---|
| 处理器 | 双核 Xtensa LX7 @240MHz | 双核 64-bit **Cortex-A35 @1.5GHz**（512KB L2）+ **Cortex-M33 @400MHz** |
| 系统形态 | FreeRTOS/裸机，无 MMU | 完整 **OpenSTLinux**（TCP/IP 栈、systemd 服务、ctest）+ 裸机实时核 |
| 视频能力 | 无硬件编码器，软件处理受限 | 片上 **DCMIPP 摄像头管线（ISP）+ 硬件 H.264 编码器** + 3D GPU |
| 实时控制 | 与业务逻辑抢占同一核 | **M33 独立实时核**：100Hz 采样 / 50Hz 闭环不被 Linux 调度抖动 |
| 跨核架构 | — | **OpenAMP/RPMsg** 虚拟串口跨核通信，固件经 remoteproc 独立升级 |
| 网络 | 集成 Wi-Fi | 千兆以太网 + 外部 Wi-Fi 浮标，有线/无线分层组网 |
| 工程生态 | Arduino/ESP-IDF | Yocto/OpenSTLinux、STM32CubeIDE、GStreamer、OpenAMP 全栈工业生态 |

**一颗芯片，两种灵魂**：A35 侧用 Linux 获得"桌面级"软件能力（GStreamer 管线、systemd 服务化、完整 TCP/IP 与单元测试设施），M33 侧以裸机保住硬实时（微秒级 PWM 时基、确定性闭环周期），两侧经 RPMsg 以严格定义的协议对话——

——工业机器人/自动驾驶域控制器的经典异构架构，我们尝试将其在作品上落地。

## 执行器与感知系统

### 动力系统（M33 · 16 路 PWM · PCA9685 经 I²C 驱动）

| 通道 | 负载 | 用途 |
|---|---|---|
| CH0–CH9 | 10 路舵机（0–180°） | 关节角度控制（机械臂），支持单路/全部/中位/组同步 |
| CH10–CH13 | 4 路垂直推进器 | 升沉基准 + 横滚/俯仰 PID 修正 |
| CH14–CH15 | 2 路水平推进器 | 水平分组/独立控制，双同步模式 |

推进器命令值为 −100%~+100%，按 `PWM_us = 1500 + 5 × command` 线性映射至 1000~2000µs，安全中值在上电与异常时强制锁存。

### 传感器接入（按接口分离，独立采集链）

| 传感器 | 类型 | 协议 | 用途 |
|---|---|---|---|
| MPU6500 | 六轴惯性 | I²C | 姿态解算（100Hz）、三维可视化 |
| DYP-L08 | 超声测距 | UART | 距离探测，有效窗口判定与分级提示 |
| DHT11 | 温湿度 | 单总线 | 舱内环境反馈 |
| INA226 | 电压电流 | I²C | 供电监测与标定电量估计 |

## 核心技术特性

### 1. 异构双核 + "双盲"三层协议架构

系统划分为三个严格解耦的层次，任何一层可独立替换、独立测试、独立演进：

- **Windows 只理解 Windows↔A35 业务协议**——不感知 M33 ASCII 协议、不接触 RPMsg；
- **A35 是唯一协议转换者与权威状态来源**——执行器通道映射、安全裁决、模式联锁全部收敛于此；
- **M33 只面向 RovControl 语义**——不知道 Windows 的存在。

关键机制：CRC16-CCITT-FALSE 帧校验、四位 SEQ/ACK 请求生命周期、双优先级命令队列（急停抢占）、迟到响应隔离、指数退避重连、连接即推送权威状态（StateEventV2）+ 变化重推 + 1Hz 兜底。

### 2. 低延迟视频链路（无 RTSP 的自愈推流）

DCMIPP/ISP 采集 → 片上硬件 H.264 编码 → RTP over UDP（动态 PT=96、MTU 1400）；SPS/PPS 每 1s 带内重发、关键帧间隔 1s，接收端**迟入 ≤1s 自动同步**；1080p/720p 随流动态切换。岸端 D3D11 硬解 + OpenGL 渲染，管线总线错误/断流**自动重建**；主页与指令页多视图经 VideoFrameHub 共享单解码管线最新帧（零拷贝）。

### 3. M33 本地姿态稳定闭环

MPU6500 100Hz 采样 → 姿态估计（互补滤波）→ Roll/Pitch 双轴 PID → 四路垂直推进器混控输出（50Hz）。闭环完全运行在 M33 本地，**即使岸端断线、Linux 侧停机，姿态稳定依旧工作**——这是把控制面从业务面剥离的架构收益。

### 4. 岸端 AI 目标识别

ONNX Runtime 运行 YOLO 系检测模型，推理后端自动探测降级：CUDA/TensorRT → DirectML → OpenVINO → CPU，适配从独显到核显的任意机器。解码线程与推理线程经**无锁 SPSC 环形缓冲**衔接并采用 drain-latest 策略——只处理最新帧，网络抖动不产生识别积压；检测框以归一化坐标叠加于双视图。

### 5. 安全与失效保护体系

- **三级停止锁存**：总使能/垂直/水平独立 Stop-Move 锁存，急停后重新使能**不恢复旧输出**；
- **急停抢占**：优先级 Estop > Emergency > Stop/Move > 普通命令，板端急停 ACK 实测往返 5.1~7.2ms（均值 **6.4ms**，20 轮）；
- **断线回退**：网关按配置自动停机，终端重连**不重放旧指令**，开关联动失败/超时自动回退并告警；
- **数据有效性先于显示**：遥测帧四重校验（长度/魔数/版本/CRC16）坏包静默丢弃，传感器数据带有效位与 TTL 判定，DYP 无效值（如 65533）正确识别不误导操作者；
- **运行时看门狗**：MPU 数据链路看门狗监测跨核链路健康，异常时自动重启网关并由 systemd 恢复 M33 与自检流程。

### 6. 一体化操作终端（工业级 GUI 工程）

Qt 6 Fluent 风格无边框界面（主页/指令/设置三页），Quick3D 三维舱体姿态实时渲染；执行器滑条为**三态显示**（目标值/已发送/A35 确认值）；全部 7 个模式开关运行 PendingSwitchState 事务模型（进度环、NACK、超时回退、断线回退、协议不一致告警）；告警中心三级筛选。线程模型遵循工业级实践：Worker-Object 事件驱动、无锁环形缓冲、`shared_mutex` + `alignas(64)` 防伪共享、GUI 线程零阻塞 I/O、退出逆序释放。

## 构建与运行

> 完整环境要求、部署与运维见各工程 README；以下为最短路径。

**Salacia_Terminal**（Windows，需 VS2026/Qt 6.11/GStreamer/ONNX Runtime）：

```bat
cmake --preset Release-x64
cmake --build out/build/release
```

**Gateway_A35**（板端 OpenSTLinux）：

```bash
cmake -S /home/root/gateway -B /home/root/gateway/build -DCMAKE_BUILD_TYPE=Release
cmake --build /home/root/gateway/build -j"$(nproc)"
ctest --test-dir /home/root/gateway/build --output-on-failure
```

**CamStream**（板端）：

```bash
cmake .. && make -j$(nproc)
./camstream_1080p /dev/video1 <主机IP> 5000 4000
```

**ROV_M33**：STM32CubeIDE 打开 `STM32CubeIDE/CM33/NonSecure`，以 `CA35TDCID_m33_ns_sign` 配置构建，按 DEVELOPMENT.md 流程校验 SHA-256 后部署至 `/lib/firmware/`。
